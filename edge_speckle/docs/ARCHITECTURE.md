# 工程架构

CPU负责文件解码、形状/类型检查、配置、结果保存。GPU负责图像/扫描特征、二维匹配、亚像素、粗细位移传递、DPC和FFT积分。CPU样条作为明确可选后端保留。

```text
文件/采集数组
  → RunConfig＋输入契约
  → WSVT会话 / WXST会话
      → 显式参考准备 → 可复用参考HWD描述子
      → 样品前端/搜索 → 粗层位移
      → 计划样条 → 细层搜索 → DPC → 相位
  → 独立输出数组＋计时记录
  → 结果契约检查 → NPZ＋JSON
```

两个方法共享匹配、样条、后处理和记录设施。WSVT沿扫描轴归一化后建立空间金字塔，WXST在每层局部模板上归一化；两者前端分别实现，不能用一个帧数开关互相替代。

原生代码使用一个 CUDA 翻译单元。`primitives.cuh → features.cuh → cached_match.cuh → edge_kernels.cu` 保持原来编译顺序，只把父目录 `.cu` 引用改为包内显式依赖。当前不为形式上的分层拆开设备内联函数，以免引入设备链接和算术重排。后续新增 kernel 在 `native/` 中注册，不反向引用历史实验文件。

统一物理 DRAM 下，主机数组与 GPU 缓冲区仍有各自的访问路径。默认复用设备缓冲区并显式写入/下载；没有在未测量的情况下改为 `cudaMallocManaged`。WXST保留重用率高的参考描述子，融合只用一次的样品特征。WSVT保留原始16位输入，统计用双精度、归一化与匹配使用float32。相位点运算仍存在临时张量。

会话拥有一个CUDA设备、一条创建时的流、计划和缓冲区。`prepare_reference` 完成后才能 `solve`；改变参考必须重新准备。样条权重和FFT缓存可复用。每次公开求解同步后返回独立结果。`download=False` 只用于内部计时/流水线实验，不返回借用数组。

公开配置要求显式几何参数；总半窗10及其它已实现数学参数固定。WSVT重排必须显式解锁。对未知参数、错误模式、错误帧数、非有限输入、浮点强制转uint16和已有结果目录直接报错。

构建与运行分开。源码包不携带数据、实验结果或可假定跨平台使用的二进制。原生库在设备上构建并记录工具链与哈希；运行报告引用这些记录。CPU参考需要C++20/FFTW，独立构建，避免将GPU包的g++17需求误当成原CPU需求。
